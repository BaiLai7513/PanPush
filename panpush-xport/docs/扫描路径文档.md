> 用途：给 `panpush`（或任何需要 root 直读网盘凭据的工具）提供**逐站点的精确扫描路径**：读哪个包、哪个文件、哪个键/正则、读出来是什么。
> 全部路径 **2026-10-11 在本机（OnePlus PKR110 / Android 15 / APatch）实测核实**。

## 1. 通用读取方法

### 1.1 XML 类（shared_prefs）
直接 root 读，无锁问题：
```bash
su -c "cat /data/data/<pkg>/shared_prefs/<file>.xml"
```

### 1.2 SQLite 类（databases / Cookies）
**活库会被 App 独占锁**，必须「复制 DB + 同目录的 `-journal` / `-wal` / `-shm` 后再读」：
```bash
P=/data/data/<pkg>/databases/0.db
T=/tmp/rd_$$
mkdir -p $T
cp $P $T/; cp $P-wal $T/ 2>/dev/null; cp $P-shm $T/ 2>/dev/null; cp $P-journal $T/ 2>/dev/null
sqlite3 $T/0.db '...'      # 或 python3 -c "import sqlite3; ..."
```
> WebView 的 cookie 库同理：复制 `Cookies` + `Cookies-journal` + `Cookies-wal`。

### 1.3 `encrypted_value` 的判读
WebView cookie 表字段 `value` / `encrypted_value`：
- `encrypted_value` 长度为 **0** → 明文，直接读 `value`；
- 非 0 → 加密（一般 v10/v11），本机多数站点为明文。

## 3. 逐站点详解

### 3.1 迅雷云盘 —— `com.xunlei.downloadprovider`

**路径**：`/data/data/com.xunlei.downloadprovider/shared_prefs/`

| 文件 | 关键键 | 内容样例 |
|---|---|---|
| `auth_pref.xml` | `credentials_Xp6vsxz_7IYVw2BB` | JSON：`access_token`(RSA-JWT)、`refresh_token`、`user_id`、`expires_at` |
| `xl-acc-captcha-token.xml` | `<hash>captchatoken` / `<hash>expiresat` | `ck0.…`（多个会话各一个） |
| `__device_info_new__.xml` | `device_id_new` / `unique_id` / `hubble_id` | `34068a3cec7abb281388182709f8ae3c` |

**三件套** = `access_token` + `captchatoken` + `device_id`。

```bash
B=/data/data/com.xunlei.downloadprovider/shared_prefs
su -c "cat $B/auth_pref.xml"
su -c "cat $B/xl-acc-captcha-token.xml"
su -c "cat $B/__device_info_new__.xml"
```

> ⚠️ `access_token` 有效期约 2 小时（`expires_in:7200`），实测已过期 → 需配 `refresh_token` 续期，或让迅雷 App 刷新一次。
> ⚠️ panpush 还会找 `login_user.xml`，但**迅雷这边没有该文件**（它属于 123，见 3.3）。

### 3.2 阿里云盘 —— `com.alicloud.databox`

**路径**：`/data/data/com.alicloud.databox/databases/0.db` → 表 `tb_user_info`（1 行）

字段（实测）：
```
user_id, nick_name, drive_id, access_token, refresh_token,
expires_in, expire_time, token_type, user_data, ...
```

```bash
T=/tmp/ali_$$; mkdir -p $T
B=/data/data/com.alicloud.databox/databases/0.db
cp $B $T/; cp $B-wal $T/ 2>/dev/null; cp $B-shm $T/ 2>/dev/null
sqlite3 $T/0.db 'select drive_id,access_token,refresh_token from tb_user_info'
```

### 3.3 123 云盘 —— `com.mfcloudcalculate.networkdisk`

**路径**：`/data/data/com.mfcloudcalculate.networkdisk/shared_prefs/login_user.xml`

| 键 | 内容 |
|---|---|
| `userToken` | `Bearer eyJ…`（JWT，**这就是解析要的 token**） |
| `userId` | `1854398463` |
| `loginType` | `3` |

辅助：`shared_prefs/FlutterSharedPreferences.xml` → `flutter.loginUUID`、`flutter.TrackingInfo`（含 `loginStatus`）。

**panpush 用的正则**（从其 dex 提取）：
```
name="userToken">\s*(?:Bearer\s+)?([A-Za-z0-9._\-]{20,})
```

```bash
su -c "cat /data/data/com.mfcloudcalculate.networkdisk/shared_prefs/login_user.xml"
# 也可：/data/user/0/com.mfcloudcalculate.networkdisk/shared_prefs/login_user.xml（同路径软链）
```

### 3.4 百度网盘 —— `com.baidu.netdisk`

**路径**：`/data/data/com.baidu.netdisk/app_webview_com.baidu.netdisk/Default/Cookies`

- 这是**百度 App 自己的 WebView cookie 库**（不是 panpush 自己的）。
- 实测含 42 条百度相关 cookie：`BDUSS` / `BDUSS_BFESS`（`.baidu.com`、`.hao123.com`、`.nuomi.com`）、`STOKEN`、`PTOKEN`、`BAIDUID` 等。
- 同目录还有分进程的库：`app_webview_com.baidu.netdisk:p2p` / `:swan0` / `:remote` / `:operator_thumbnail`。

```bash
T=/tmp/bd_$$; mkdir -p $T
B=/data/data/com.baidu.netdisk/app_webview_com.baidu.netdisk/Default
cp $B/Cookies $T/; cp $B/Cookies-journal $T/ 2>/dev/null; cp $B/Cookies-wal $T/ 2>/dev/null
sqlite3 $T/Cookies "select host_key,name from cookies where name like '%BDUSS%'"
```

> 百度也可走**应用内 WebView 登录**（`BDUSS` 非 httpOnly），两条路都行，留一条即可。

### 3.5 夸克 —— `com.quark.browser`

**路径**（真实存在）：
```
/data/data/com.quark.browser/app_u46_webview/Default/Cookies
/data/data/com.quark.browser/app_u4_webview/Default/Cookies
```

**实测内容**（关于夸克的 cookie）：
- `b.quark.cn`：`__itrace_wid` / `b-user-id`（跟踪类）
- `m.quark.cn`：`XSRF-TOKEN` / `_ch` / `_ss` / `phid` / `sm_*`（会话类）
- **没有 `pan.quark.cn`，也没有 `__puus` / `ctoken`**

> ⚠️ **夸克网盘令牌不在浏览器 cookie 库里** → 大概率在夸克账号的加密存储（哈希命名的 `.sp`）中，root 直读难度大。
> ⚠️ panpush dex 里还引用了 `app_uc_webview/Default/Cookies`，**该目录在本机不存在**（实际是 `app_u4_webview`）——命名有误。
> **结论：夸克建议走「手动粘贴」，不要指望 root 直读。**

### 3.6 UC —— `com.UCMobile`

**路径**：`/data/data/com.UCMobile/app_webview/Default/Cookies`

- 与夸克同源（UC 内核），同样**不含夸克网盘登录令牌**。
- panpush 引用了该包名，推测是想从 UC/夸克浏览器取 token；**实测此路不通**。

### 3.7 蓝奏云

无需凭据，**不扫描**。

## 4. panpush 现状对照（dex 里写死的路径）

从 `classes*.dex` 字符串提取，panpush 实际使用的路径：

| 站点 | panpush 写的路径 | 与实测是否一致 |
|---|---|---|
| 迅雷 | `com.xunlei.downloadprovider/shared_prefs/{auth_pref,xl-acc-captcha-token,__device_info_new__}.xml` | ✅ 一致 |
| 阿里 | `com.alicloud.databox/databases/0.db` | ✅ 一致 |
| 123 | `/data/data/com.mfcloudcalculate.networkdisk` + `shared_prefs/login_user.xml` + `userToken` 正则 | ✅ 一致（**123 路径写对了**） |
| 百度 | `app_webview_com.baidu.netdisk/Default/Cookies` | ✅ 一致 |
| 夸克 | `com.quark.browser` + `app_u46_webview` +（`app_uc_webview` 命名有误） | ⚠️ 目录名有误 |
| UC | `com.UCMobile` | ⚠️ 数据里无网盘令牌 |

**结论**：panpush 的**读取路径基本全对**（含 123）。真正的问题是——
1. **检测环节（`PackageManager` 判 App 是否安装）在包可见性下失败 → 提前 return，根本没走到读取**；
2. 夸克/UC 的**数据源本身就没有网盘令牌**，读也读不到，应改手动粘贴。

---

## 5. 建议

1. **扫描逻辑按「文件是否存在」而非「包名是否存在」**：直接 `cat` / `ls` 目标文件，能读到就用。
2. **优先级**：迅雷 / 阿里 / 123 / 百度 → root 直读；夸克 / UC → 手动粘贴；蓝奏 → 免登录。
3. **有效性校验**：读出后检查令牌时间戳（迅雷 `expires_at`、123 JWT `exp`、阿里 `expire_time`），过期提示刷新或手动粘贴。
4. **失败降级**：任何站点读不到 → 给出「手动粘贴」入口，而不是判「无效」。

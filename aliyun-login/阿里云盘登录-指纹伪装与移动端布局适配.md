# 阿里云盘登录 —— 指纹伪装与移动端布局适配（测试文档）

> 问题：阿里云盘**用手机 UA 根本登不了**（被推去下载 App / 不给登录入口）；
> 换成 Linux / Windows 桌面 UA 能出登录界面，但**在手机 WebView 里会卡人机校验（滑块/无痕验证）**。
> 本文说明**为什么卡**、**怎么测**、**怎么伪装指纹绕过**，以及**桌面页在小屏上怎么适配布局**。
> 设备基线：OnePlus PKR110 / Android 15 / APatch Root。日期：2026-10-12。

---

## 0. 现象与结论

| 场景 | 结果 |
|---|---|
| 手机 UA（Android/iPhone） | ❌ 被识别为移动端 → 推 App / 不给登录入口 |
| 桌面 UA（Windows） | ✅ 出登录界面，但**手机 WebView 内点登录 → 弹人机校验，且常验证不通过** |
| 桌面 UA + 完整指纹伪装（真机验证） | ✅ 预期可过（本文给出实现，待联调最终确认） |

> **一句话**：只改 UA 是不够的。阿里的反爬（`um`/Alibaba 无痕验证）会同时读
> **请求头（Client Hints）** 和 **JS 指纹**，发现"UA 说你是 Windows，但你的内核处处是 Android"，
> 就判定为可疑环境 → 抛人机校验。**必须把 UA 与指纹伪装到一致。**

---

## 1. 根因：桌面 UA + 手机内核，两处自相矛盾

### 1.1 请求头层面的矛盾（Client Hints）

Android WebView 即使在 `settings.userAgentString` 设了桌面 UA，
**`Sec-CH-UA-*` 系列头仍会按内核真实设备发送**，典型对照：

| 请求头 | 真实 Android WebView | 伪装的桌面 Chrome | 是否露馅 |
|---|---|---|---|
| `User-Agent` | 已被改成 Windows | Windows ✓ | ✅ 一致 |
| `Sec-CH-UA-Mobile` | `?1` | `?0` | ❌ **露馅** |
| `Sec-CH-UA-Platform` | `"Android"` | `"Windows"` | ❌ **露馅** |
| `Sec-CH-UA-Platform-Version` | 如 `"13"`/`"15"` | `"10.0.0"` | ❌ **露馅** |
| `Sec-CH-UA-Arch` / `Bitness` | `arm` / `64` | `x86` / `64` | ❌ **露馅** |

> UA 说 Windows，`Sec-CH-UA-Platform` 说 Android —— 这是最直接、最致命的矛盾。

### 1.2 JS 指纹层面的矛盾（`navigator`）

页面里的反爬脚本还会读 `navigator` / WebGL / 触摸能力，Android WebView 的默认值与桌面 Chrome 差距明显：

| 指纹项 | Android WebView 默认 | 桌面 Chrome | 矛盾 |
|---|---|---|---|
| `navigator.platform` | `Linux armv8l` / `Linux aarch64` | `Win32` | ❌ |
| `navigator.userAgentData.platform` | `Android` | `Windows` | ❌ |
| `navigator.userAgentData.mobile` | `true` | `false` | ❌ |
| `navigator.maxTouchPoints` | `>0`（如 5） | `0` | ❌ |
| `'ontouchstart' in window` | `true` | `false` | ❌ |
| `navigator.vendor` | `""`（空） | `Google Inc.` | ❌ |
| `navigator.plugins.length` | `0` | `5`（PDF 系列） | ❌ |
| `navigator.webdriver` | 视实现 | `false` | ⚠️ |
| `window.chrome` | `undefined` | 存在 | ❌ |
| WebGL `UNMASKED_RENDERER_WEBGL` | `Adreno (TM) ...` / `Mali-...` | `ANGLE (Intel...)` | ❌ **露馅** |
| `navigator.hardwareConcurrency` / `deviceMemory` | 视机器 | 常见 `8`/`8` | ⚠️ |

> **结论**：手机内核的默认指纹是一整套"移动端证据"。只改 UA，等于举着 Windows 的牌子、浑身写着 Android。

## 2. 测试方法（先量出来，再改）

### T1. 请求头检测（抓真实发出的 Client Hints）

在 `WebViewClient.shouldInterceptRequest` 里打印请求头，或用一个回显服务验证：

```kotlin
web.webViewClient = object : WebViewClient() {
    override fun shouldInterceptRequest(
        view: WebView, req: WebResourceRequest
    ): WebResourceResponse? {
        if (req.url.toString().contains("alipan.com")) {
            req.requestHeaders.forEach { (k, v) ->
                Log.d("HDR", "$k = $v")   // 重点看 Sec-CH-UA-*
            }
        }
        return super.shouldInterceptRequest(view, req)
    }
}
```

或用外部回显接口（加载 `https://httpbin.org/headers` 看返回的 `sec-ch-ua*`）**自测**改造前后差异。

**判定**：改造前应看到 `sec-ch-ua-mobile: ?1`、`sec-ch-ua-platform: "Android"`；改造后应为 `?0` / `"Windows"`。

### T2. JS 指纹 dump（一行看全）

在登录页 `evaluateJavascript` 注入探测脚本，把关键指纹打回来：

```js
(function(){
  var g = {};
  try { g.platform   = navigator.platform; } catch(e){}
  try { g.vendor     = navigator.vendor; } catch(e){}
  try { g.ua         = navigator.userAgent; } catch(e){}
  try { g.touch      = navigator.maxTouchPoints; } catch(e){}
  try { g.ontouch    = ('ontouchstart' in window); } catch(e){}
  try { g.plugins    = navigator.plugins.length; } catch(e){}
  try { g.webdriver  = navigator.webdriver; } catch(e){}
  try { g.chrome     = (typeof window.chrome); } catch(e){}
  try { g.uadata     = navigator.userAgentData && navigator.userAgentData.platform; } catch(e){}
  try { g.uamobile   = navigator.userAgentData && navigator.userAgentData.mobile; } catch(e){}
  try {
    var c = document.createElement('canvas').getContext('webgl');
    var d = c.getExtension('WEBGL_debug_renderer_info');
    g.glVendor   = c.getParameter(d.UNMASKED_VENDOR_WEBGL);
    g.glRenderer = c.getParameter(d.UNMASKED_RENDERER_WEBGL);
  } catch(e){}
  return JSON.stringify(g);
})()
```

**判定**：改造前 `platform=Linux...`、`touch>0`、`ontouch=true`、`plugins=0`、`glRenderer=Adreno/Mali`、`uamobile=true`；改造后应全部与桌面 Chrome 一致。

### T3. 人机校验触发复现

1. 桌面 UA、**不做任何指纹伪装** → 走到登录提交 → 观察是否弹滑块/无痕验证；
2. 桌面 UA、**做指纹伪装** → 同样操作 → 观察是否直接过。
3. 重复 ≥3 次，确认不是偶发。

> 注意：阿里人机校验还可能受**账号风控、IP、频率**影响，测试时用同一账号、同一网络对比，才能归因到指纹。

## 3. 解决方案：三处一起伪装，保持"全链路一致"

### 3.1 请求头伪装（主框架）

`WebView.loadUrl(url, additionalHttpHeaders)` 只作用于**主框架请求**：

```kotlin
private val DESKTOP_HEADERS = mapOf(
    "User-Agent"                  to DESKTOP_UA,
    "Sec-CH-UA"                   to "\"Chromium\";v=\"120\", \"Google Chrome\";v=\"120\", \"Not?A_Brand\";v=\"24\"",
    "Sec-CH-UA-Mobile"            to "?0",
    "Sec-CH-UA-Platform"          to "\"Windows\"",
    "Sec-CH-UA-Platform-Version"  to "\"10.0.0\"",
    "Sec-CH-UA-Arch"              to "\"x86\"",
    "Sec-CH-UA-Bitness"           to "\"64\"",
    "Sec-CH-UA-Full-Version-List" to "\"Chromium\";v=\"120.0.0.0\", \"Google Chrome\";v=\"120.0.0.0\"",
    "Accept-Language"             to "zh-CN,zh;q=0.9,en;q=0.8"
)
web.loadUrl(HOME, DESKTOP_HEADERS)
```

> ⚠️ **局限**：`loadUrl` 的头**不会自动带到 XHR/子资源**。若校验脚本是从 XHR 里读 Client Hints，需要
> 用 `shouldInterceptRequest` 重建请求（自建 HTTP 客户端取回后再包成 `WebResourceResponse`）才能全量覆盖，
> 实现较重；实践上多数场景**JS 指纹是主要判据**，先做 §3.2 即可，§3.1 作为加强项。

### 3.2 JS 指纹伪装（关键，注入越早越好）

```kotlin
private const val FINGERPRINT_JS = """
(function(){
  // ---- 1) navigator 基础项 ----
  var D = function(o,k,v){ try{ Object.defineProperty(o,k,{get:function(){return v;},configurable:true}); }catch(e){} };
  D(navigator,'platform','Win32');
  D(navigator,'vendor','Google Inc.');
  D(navigator,'maxTouchPoints',0);
  D(navigator,'webdriver',false);
  D(navigator,'hardwareConcurrency',8);
  D(navigator,'deviceMemory',8);
  D(navigator,'language','zh-CN');
  D(navigator,'languages',['zh-CN','zh','en']);
  D(navigator,'pdfViewerEnabled',true);

  // ---- 2) plugins / mimeTypes 造出桌面非空 ----
  var plugNames = ['PDF Viewer','Chrome PDF Viewer','Chromium PDF Viewer',
                   'Microsoft Edge PDF Viewer','WebKit built-in PDF'];
  var fakePlugins = plugNames.map(function(n){ return {name:n, filename:'internal-pdf-viewer', description:'Portable Document Format'}; });
  fakePlugins.item = function(i){ return this[i]; };
  fakePlugins.namedItem = function(n){ return this.find(function(p){return p.name===n;}) || null; };
  D(navigator,'plugins',fakePlugins);

  // ---- 3) userAgentData（Client Hints JS 侧）----
  var hev = { architecture:'x86', bitness:'64', model:'', platform:'Windows',
              platformVersion:'10.0.0', uaFullVersion:'120.0.0.0',
              fullVersionList:[{brand:'Chromium',version:'120.0.0.0'},{brand:'Google Chrome',version:'120.0.0.0'}],
              wow64:false };
  var uaData = {
    brands:[{brand:'Chromium',version:'120'},{brand:'Google Chrome',version:'120'},{brand:'Not?A_Brand',version:'24'}],
    mobile:false, platform:'Windows',
    getHighEntropyValues:function(){ return Promise.resolve(hev); },
    toJSON:function(){ return {brands:this.brands, mobile:this.mobile, platform:this.platform}; }
  };
  D(navigator,'userAgentData',uaData);

  // ---- 4) window.chrome ----
  if(!window.chrome) window.chrome = {};
  window.chrome.runtime = window.chrome.runtime || {};
  window.chrome.app = window.chrome.app || {isInstalled:false};

  // ---- 5) 触摸特征抹掉 ----
  try{ Object.defineProperty(window,'ontouchstart',{get:function(){return undefined;},configurable:true}); }catch(e){}
  try{ delete window.ontouchstart; }catch(e){}

  // ---- 6) WebGL 指纹（Android GPU → Intel/ANGLE）----
  function patchGL(proto){
    if(!proto) return;
    var orig = proto.getParameter;
    proto.getParameter = function(p){
      if(p===37445) return 'Google Inc. (Intel)';
      if(p===37446) return 'ANGLE (Intel, Intel(R) UHD Graphics 620 Direct3D11 vs_5_0 ps_5_0, D3D11)';
      return orig.call(this,p);
    };
  }
  patchGL(window.WebGLRenderingContext && WebGLRenderingContext.prototype);
  patchGL(window.WebGL2RenderingContext && WebGL2RenderingContext.prototype);
})();
"""
```

**注入时机**（Android WebView 没有原生 `document_start` 钩子，用组合拳尽量提前）：

```kotlin
web.webViewClient = object : WebViewClient() {
    override fun onPageStarted(view: WebView, url: String, fav: Bitmap?) {
        view.evaluateJavascript(FINGERPRINT_JS, null)   // 尽早
    }
    override fun onPageFinished(view: WebView, url: String) {
        view.evaluateJavascript(FINGERPRINT_JS, null)   // 补一次，防被覆盖
        forceDesktopViewport()
        probe(false)
    }
}
```

> **要点**：`onPageStarted` 时注入通常早于页面内联脚本执行；若发现仍被站点脚本抢跑，
> 可改用 `WebViewClient.onLoadResource` 配合、或把伪装脚本作为**首个**注入
> （多注入几次代价很小）。SPA 场景下指纹校验多在交互时读取，一般够用。

## 4. 移动端布局适配（桌面页塞进手机屏）

桌面页在手机上**不缩放会横向溢出、缩放过头又看不清**。目标：**整页按屏宽铺满、可读、可缩放、滑块好点**。

### 4.1 基础设置

```kotlin
web.settings.apply {
    useWideViewPort = true           // 允许按 viewport meta 渲染桌面宽度
    loadWithOverviewMode = true      // ★ 把整页缩到屏宽（防横向溢出）
    setInitialScale(0)               // 由内容决定，交给 overview
    setSupportZoom(true)
    builtInZoomControls = true
    displayZoomControls = false      // 隐藏 +/- 按钮，保留双指缩放
    // 桌面 UA（见 §3.1）
}
```

### 4.2 注入 viewport（控制缩放比例，别让字太小）

`loadWithOverviewMode` 会按页面的 `viewport` 宽度缩放到屏宽。桌面页多为 `width=1280`，
缩到手机屏会**偏小**。把逻辑宽度调小到 800~1000，字号更合适：

```kotlin
private fun forceDesktopViewport() {
    web.evaluateJavascript(
        "(function(){" +
        "var W=900;" +                                  // ← 逻辑宽度，越大小字越小
        "var m=document.querySelector('meta[name=\"viewport\"]');" +
        "if(!m){m=document.createElement('meta');m.setAttribute('name','viewport');" +
        "document.getElementsByTagName('head')[0].appendChild(m);}" +
        "m.setAttribute('content','width='+W+', initial-scale=1, maximum-scale=4, user-scalable=yes');" +
        "})()", null)
}
```

> **调参**：登录按钮/输入框太小 → 把 `W` 调小（如 `760`）；页面被裁切 → 调大（如 `1080`）。
> `user-scalable=yes` + `maximum-scale=4` 保证人能放大看清验证码。

### 4.3 容器与输入法

```xml
<!-- AndroidManifest.xml -->
<activity android:name=".login.AliyunLoginActivity"
    android:configChanges="orientation|screenSize|keyboardHidden|screenLayout|smallestScreenSize"
    android:windowSoftInputMode="adjustResize" />
```

- WebView 宽高都 `match_parent`，放 `FrameLayout`，**不要固定 dp**；
- `adjustResize` 让软键盘弹出时页面不被顶飞（输入账号/验证码时关键）；
- `configChanges` 避免旋转/键盘变化重建 WebView 丢失登录态。

### 4.4 人机校验（滑块）可用性

- 滑块靠 `touch` 事件；§3.2 **只改 `navigator` 属性、不拦截真实触摸**，所以**不影响**拖拽；
- 若滑块过小拖不准 → 调小 §4.2 的 `W`（放大整体），或临时允许双指放大再拖；
- 校验弹层可能是 WebView 内浮层：确保 `setSupportMultipleWindows(false)`，避免它跑到新窗口。

## 6. 风险与备注

1. **不是 100% 保证过校验**：阿里风控是动态的，"指纹一致"只是必要条件之一；还受账号、IP、频率影响。若仍被拦，考虑：换网络/IP、降低操作频率、或退回"用户手动在浏览器登录后粘贴 token"的兜底方案（见《应用内登录 vs Root直读 差异与选型》）。
2. **头覆盖不完整**：`loadUrl` 只覆盖主框架，XHR/子资源仍可能带 Android 头（§3.1 局限）。如需彻底，用 `shouldInterceptRequest` 重建请求。
3. **注入时机**：Android WebView 无 `document_start`，靠 `onPageStarted` + `onPageFinished` 组合，极端竞态下可能被站点脚本抢先；多注入几次可缓解。
4. **合规**：伪装指纹属于对抗网站反爬机制，仅用于**自有账号、个人合法用途**的正常登录；请遵守服务条款与当地法律法规。
5. **待真机联调**：C4~C8 的最终结果需在真实账号登录下确认（本次为机制分析与方案，未含真实登录）。

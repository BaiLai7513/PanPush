# 应用列表扫描（读取凭据前的第 0 步）

> 用途：在 root 直读任意 App（网盘凭据等）之前，**先扫描已安装应用列表**，决定哪些站点可用。
> 设备：OnePlus PKR110 / Android 15 / APatch Root
> 日期：2026-10-11

---

## 0. 为什么要先扫应用列表

1. **决定哪些站点"可 root 直读"**：目标 App 没装 → root 直读无意义（只能手动粘贴）。
2. **绕开包可见性**：普通 App 的 `PackageManager.getPackageInfo` / `pm list packages` 会被 Android 11+ 的**包可见性**屏蔽
   —— 实测同一台机：**panpush 身份只能看到 1 个包，root 能看到 688 个**。
   → **应用列表必须用 root 扫。**
3. **包名会变 / 多渠道 / 大小写敏感**：同一站点可能有多个包名
   （夸克 `com.quark.browser`、UC `com.UCMobile` 大写），要用「**候选列表 + 忽略大小写兜底**」，而不是写死一个。

---

## 1. 怎么扫（全部走 root）

```bash
# 1) 全量包名
su -c "pm list packages"

# 2) 只筛目标站点
su -c "pm list packages | grep -iE 'xunlei|databox|mfcloud|quark|UCMobile|baidu.netdisk'"

# 3) 兜底：直接看数据目录（比 pm 更"抗屏蔽"）
ls /data/data | grep -iE 'xunlei|databox|mfcloud|quark|UCMobile|baidu.netdisk'

# 4) 单个包存在性
su -c "pm path com.xunlei.downloadprovider"
```

## 3. 判定逻辑（建议实现）

```kotlin
// 1) root 扫到全量包名
val pkgs = root("pm list packages")
    .lineSequence().map { it.removePrefix("package:") }.toSet()

// 2) 候选匹配（大小写敏感优先，忽略大小写兜底）
fun match(candidates: List<String>) =
    candidates.firstOrNull { pkgs.contains(it) }
        ?: candidates.firstOrNull { c -> pkgs.any { it.equals(c, ignoreCase = true) } }

// 3) 得到"本机可 root 直读"的站点集合
val readable = SITES.filter { match(it.candidates) != null }

// 4) 【关键】再用"文件存在性"兜底：
//    即使包名没匹配到，只要目标文件存在，也判为可用（比包名更可靠）
```

---

## 4. 关键提醒

- **应用列表只是"提示"，最终以「目标文件是否存在」为准**：文件在 → 就能读，不必纠结包名。
- **绝不用非 root 的 `getPackageInfo`**（包可见性会误判为"未安装"）。这是常见的"未检测到 APP"根因。
- **扫不到 App ≠ 不能读**；读不到文件才需要降级到「手动粘贴」。

## 5. 实测样例（本机）

```text
$ su -c "pm list packages | grep -iE 'xunlei|databox|mfcloud|quark|UCMobile|baidu.netdisk'"
package:com.xunlei.downloadprovider
package:com.alicloud.databox
package:com.mfcloudcalculate.networkdisk
package:com.baidu.netdisk
package:com.quark.browser
package:com.UCMobile
```

对照（包可见性差异）：

```text
$ su 10623 -c "pm list packages | wc -l"   # 普通 App 身份 → 1
$ pm list packages | wc -l                  # root 身份   → 688
```

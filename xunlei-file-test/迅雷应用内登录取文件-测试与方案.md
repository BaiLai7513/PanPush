# 迅雷云盘「应用内登录能否取到文件」——实测报告与实现方案

> 问题：harness 称"迅雷应用内（WebView）登录取不到文件"。本文用真机实测验证该说法，并给出可行实现。
> 设备基线：OnePlus PKR110 / Android 15 / APatch Root。日期：2026-10-12。

---

## 0. 结论

> **harness 的说法只对了一半。**
>
> - ❌ "网页登录没有网盘权限" —— **不成立**：迅雷网页版 client 的 scope 明确含 **`pan`**。
> - ✅ "拿 App 的那套方式去用网页登录的令牌，取不到文件" —— **成立**，因为网页 client 与 App client **不是同一个 client**，令牌不能混用。
> - ✅ **正确做法可以取到文件**：WebView 登录 `pan.xunlei.com` → 读取 `credentials_*` 里的 **access_token** → 用 `api-pan.xunlei.com` + `Bearer` 调列表（这正是网页版自己干的事）。

**一句话**：不是"取不到"，而是"取法要跟网页版一致，别跟 App 混"。

---

## 1. 实测证据

### 1.1 迅雷云盘 API 与鉴权（实测）

```
GET https://api-pan.xunlei.com/drive/v1/about
GET https://api-pan.xunlei.com/drive/v1/files?limit=20
Header: Authorization: Bearer <access_token>
```

用本机 App 的旧 `access_token` 调用 → **HTTP 401**：
```json
{"error":"unauthenticated","error_code":16,
 "error_description":"帐号认证失败，请重新登录",
 "details":"oidc: token is expired (Token Expiry: 2026-10-12 23:25:11 +0800)"}
```
→ 证明：**API 地址与鉴权方式正确**，该 token 只是过期。

### 1.2 迅雷网页版 client 的权限（从 `pan.xunlei.com` JS 提取，关键）

```js
c = { "pan.xunlei.com": {
      clientId: "Xqp0kJBXWhwaTpB6",              // ★ 网页端 client
      packageName: "pan.xunlei.com",
      signKey: "k&&9(rT5LU", algVersion: "1", ... } }
authorizePage: "https://i.xunlei.com/center/account/personal/oauth/",
scope: "profile offline pan sso user"            // ★★ 含 pan！
```

对照 App 的 token：`aud = Xp6vsxz_7IYVw2BB`（**另一个 client**）。
→ **网页端 client 明确带 `pan` 权限**，且网页版自己就是调 `api-pan.xunlei.com`。

### 1.3 网页版的凭证存放位置（关键）

网页 JS 中：
```js
h = function(){ return c.a.get("credentials_" + d.default.clientId) }
```
`d.default.clientId` 即 `Xqp0kJBXWhwaTpB6`，`c.a` 走 `document.cookie`。
→ **网页登录后，凭证（含 access_token/refresh_token）以 `credentials_<clientId>` 形式存放**。
→ **WebView 的 `CookieManager.getCookie()` 能读到**（httpOnly 也不影响 Native 读取）。

### 1.4 反面证据：App 侧的 `img_res_token` 不能用于列表

`xpan.spf.xml` 里 `962114367_img_res_token` 是 base64 的 JWT（res token，含 `clientid=Xp6vsxz_7IYVw2BB`、`uid=962114367`），
用它调 api-pan → **401 `failed to verify id token signature`**。
→ **资源令牌（res token）≠ 列表令牌**，别拿错。

### 1.5 登录流程

统一走 `https://xluser-ssl.xunlei.com`（+ captcha init 端点存在，实测返回 `captcha_invalid`）。
即：网页/App 共用同一套 OAuth 登录服务，各自用各自的 client。

## 2. 为什么 harness 会"取不到文件"

最可能的三种情况（按概率）：

| 情况 | 现象 | 原因 |
|---|---|---|
| **A. 抓到了 cookie，但没提取 access_token** | 有 `credentials_*` 却调不通 | cookie 里是 JSON，要**解析出 access_token** 再放 `Authorization: Bearer` |
| **B. 拿了 web token 去套 App 的调用方式** | 401 / 权限错 | web client ≠ App client，令牌不通用 |
| **C. 拿了 res_token / 别的令牌** | 401 `verify id token signature` | 令牌类型不对（见 §1.4） |

> 三种都不是"网页登录天生取不到"，而是**取令牌/用令牌的方式不对**。

## 3. 正确实现方案（应用内 WebView 登录取文件）

### 3.1 流程

```
打开 WebView（桌面 UA）→ https://pan.xunlei.com/
        │
        ▼
用户登录（扫码 / 账号密码，可能需验证码）
        │
        ▼
读取 CookieManager.getCookie("https://pan.xunlei.com")
   （并可结合 localStorage）
   → 找 "credentials_" 开头的键，解析出 access_token
        │
        ▼
Authorization: Bearer <access_token>
GET https://api-pan.xunlei.com/drive/v1/files?limit=100   ✅ 列出文件
```

### 3.2 抓取代码（关键）

```kotlin
// 登录成功后，从 cookie 里找 credentials_<clientId>
fun extractXunleiToken(): String? {
    val urls = listOf(
        "https://pan.xunlei.com", "https://xunlei.com",
        "https://i.xunlei.com", "https://xluser-ssl.xunlei.com"
    )
    val ck = urls.joinToString("; ") {
        CookieManager.getInstance().getCookie(it).orEmpty()
    }
    // cookie 里 key=value 的 value 可能是 URL 编码的 JSON："credentials_Xqp0kJBXWhwaTpB6":{...}
    return parseAccessToken(ck)
}

/** 从任意串里抠出 access_token / refresh_token。 */
private fun parseAccessToken(blob: String): String? {
    val decoded = java.net.URLDecoder.decode(blob, "UTF-8")
    // 形如 "access_token":"eyJ..."
    Regex("\"access_token\"\\s*:\\s*\"([^\"]+)\"").find(decoded)?.let { return it.groupValues[1] }
    // 兜底：直接找 JWT
    Regex("eyJ[A-Za-z0-9_-]+\\.[A-Za-z0-9_-]+\\.[A-Za-z0-9_-]+").find(decoded)?.let { return it.value }
    return null
}
```

> 建议**同时** dump `localStorage`（`evaluateJavascript`），因为不同版本可能把 `credentials_*` 放 localStorage：
> ```kotlin
> web.evaluateJavascript("JSON.stringify(localStorage)") { ls -> /* 在 ls 里找 credentials_ / access_token */ }
> ```

### 3.3 调用 API（列文件）

```bash
curl -H "Authorization: Bearer <access_token>" \
     "https://api-pan.xunlei.com/drive/v1/files?limit=100"
```

```kotlin
// OkHttp
val req = Request.Builder()
    .url("https://api-pan.xunlei.com/drive/v1/files?limit=100")
    .header("Authorization", "Bearer $accessToken")
    .build()
```

> 注意：网页 client 可能带一些普通头（如 `X-Device-Id` 等）属可选，**核心是 Bearer 令牌**。
> 若遇 401，用同账号在 `pan.xunlei.com` 抓包比对头，补齐即可。

### 3.4 建议的抓取时机

- `onPageFinished` 每次探一次；
- 同时 1.5s 轮询，直到 `credentials_*` 里出现 `access_token`；
- 命中即存 `cred_xunlei`，返回 `RESULT_OK`。

## 4. 与 Root 直读的对比（本轮实测补充）

| 项 | Root 直读 | WebView 登录 |
|---|---|---|
| 令牌来源 | App token（`auth_pref.xml`，client=`Xp6vsxz_7IYVw2BB`） | Web token（`credentials_*`，client=`Xqp0kJBXWhwaTpB6`） |
| 权限 | 含 pan | **也含 pan** |
| 有效期 | 2h + refresh | 网页 session + refresh |
| 额外依赖 | 需 captcha token（`xl-acc-captcha-token.xml` / `oauth.spf.xml`） | 网页自己处理验证码 |
| 需要 root | ✅ | ❌ |

> 两者都能到 pan；**关键是别把令牌和调用方式配错**。

## 5. 待端到端验证（本文未完成的部分）

由于本机无法代替用户完成一次真实网页登录，以下**最终一步需联调确认**：

1. 登录后 `credentials_Xqp0kJBXWhwaTpB6` 的确切存放（cookie？localStorage？）与编码（URL 编码 JSON？）；
2. 用提取到的 web access_token 调 `api-pan.xunlei.com/drive/v1/files` 是否 200；
3. 是否需要补充设备类请求头。

**验证方法**：按 §3 实现后，在真机打开迅雷登录页登录，看 `panpush.xml` 是否写入含 `access_token` 的 `cred_xunlei`，再跑一次列表请求。

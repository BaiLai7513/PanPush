# 平台对比与改进：X网盘助手 vs 我们的方案

> 对比对象：`https://x.dg22.top/`（X网盘助手，在线云解析平台）
> 对比时间：2026-10-11 · 方式：抓取站点结构 + 读其前端 JS + 后端接口实测

---

## 1. 对方的实现（实测还原）

**架构：Web 前端 + PHP 后端解析 + 推本地下载器**

```
浏览器打开 https://xljx.dg22.top/（Vue/Vite SPA，Cloudflare 后面）
        │
        ├─ GET  /api.php?action=config         ← 取站点配置（站点名/公告/是否要密码）
        ├─ GET  /get_file_list.php?share_id=…  ← 列目录（★在它服务器上解析）
        └─ POST /get_link.php                  ← 取直链（★在它服务器上解析）
        │
        └─ POST http://localhost:9999/api/v1/tasks   ← 把直链推给【你本地的 Gopeed】
           （也支持 Aria2：loadAria2Config / saveAria2Config）
```

证据：

```json
// GET https://xljx.dg22.top/api.php?action=config
{"code":200,"data":{
  "site_name":"迅雷解析-X网盘助手",
  "notice":"由于迅雷账号有下载限制，暂时只支持赞助用户使用。",
  "require_password":true, ...}}
```

```js
// 其前端 bundle 摘录
cc="/api.php"; co="/get_file_list.php"; ao="/get_link.php";
UA = "netdiskP2SP/3.0.20.138"            // 推送下载时默认 UA
opts = { name, path, selectFiles:[0], extra:{ connections:256 } }
fetch(`${host}/api/v1/tasks`, {method:"POST", ...})   // host 默认 http://localhost:9999
```

**要点**：解析在**他们的服务器**上完成（用**他们自己的网盘账号**），所以：
- 用户**不需要任何 Cookie / 登录**，纯粘贴链接即可；
- 但迅雷因"账号有下载限制"而**限定赞助用户**，且要**解析密码/卡密**。

覆盖范围（其官方主页）：夸克 / UC / 迅雷 / 百度 / 移动 / 天翼 / 联通 / 123 / 阿里 / 城通 /
微云 / 115 / 光鸭 / 蓝奏 / 蓝奏优享 / 小飞机 / QQ邮箱 / PIKPAK。

## 2. 两种方案的本质差异

| 维度 | X网盘助手 | 我们的方案（panpush + xunlei.py） |
|---|---|---|
| 解析位置 | **云端（它的服务器）** | **本地（你的设备）** |
| 凭据 | 用它自己的账号，你不用给 | 用**你自己的**账号（迅雷靠 root 直读 APP） |
| 隐私 | 分享链接要发给第三方 | 全程不出设备 |
| 费用 | 迅雷等需**赞助/卡密** | 免费 |
| 部署 | 打开网页即可 | 需设备 root + 装 APP |
| 下载器 | **Gopeed + Aria2** | Gopeed |
| 站点数 | **18+** | 5（quark/uc/baidu/123/xunlei） |
| 功能 | 解析 + 转存/列表/删除/移动/建目录/上传/分享（完整客户端） | 仅解析（刻意只读） |
| 客户端 | Windows 10+ 桌面客户端 | Termux CLI |

**一句话**：他们是"**云端代解析**"（省事但要把链接交出去、且收费点在那）；我们是"**本地自解析**"（隐私/免费，但门槛是 root 与账号）。

## 3. 可直接借鉴的改进点

### 3.1 【已实现】UA 自动探测 ✅

**发现**：对方推送下载用的默认 UA 是 `netdiskP2SP/3.0.20.138`（迅雷自家 P2SP 客户端 UA），
而我们的分享直链实测**只认 `okhttp/4.9.0`**。

实测对比（同一条分享直链 `vod0099-h04-vip-lixian`）：

| UA | 结果 |
|---|---|
| `okhttp/4.9.0` | **206（可用）** |
| `netdiskP2SP/3.0.20.138` | 403 |
| `Thunder/1.0` | 403 |
| `Mozilla/5.0` | 403 |

→ 说明**"哪个 UA 能用"取决于直链的来源/类型**（分享链 vs 平台自己账号的链）。
写死单一 UA 是脆弱的。

**改进**：在 `xunlei.py` 加入 `UA_DL_CANDIDATES` + `probe_download_ua()`：
对每个 host 用 `Range: bytes=0-0` 依次试候选 UA，取第一个 200/206 的（按 host 缓存），
可用环境变量 `XUNLEI_UA` 强制覆盖。已实测：分享链自动选中 `okhttp/4.9.0`。

### 3.2 【建议】多下载器支持（Aria2）

对方同时支持 **Gopeed 与 Aria2**。我们目前只推 Gopeed。
建议在 `Gopeed` 类旁加一个 `Aria2` 后端（JSON-RPC `aria2.addUri`），
`--downloader gopeed|aria2` 二选一。改动小、收益明确（很多安卓玩家装了 Aria2/ADM）。

### 3.3 【建议】站点覆盖扩展

差距最大的一项。优先级建议（按"是否已有可用公开接口 + 用户量"）：

| 站 | 难度 | 备注 |
|---|---|---|
| 阿里云盘（阿里） | 中 | 需 token，公开接口较规范 |
| 城通网盘 | 低 | 老站，规则稳定 |
| 天翼 / 移动 / 联通 | 中 | 需登录 |
| 蓝奏云 / 蓝奏优享 | 低 | 小而稳，收益高 |
| 115 / 微云 / PIKPAK | 高 | 风控强 |

### 3.4 【已采纳 · 已实现】推送并发按站点区分

对方统一给 `connections:256`。我们实测：
- 迅雷分享链：**8~16** 足够（服务端 ~6 Mbps 天花板，多连无益）；
- 迅雷个人云盘链：**1~4** 足够；
- 其它站点（夸克/百度）高并发确实有用。

→ 已落地为**按站点的默认连接数表**，替代全局 512：

```
DEFAULT_CONNECTIONS = {"xunlei": 16}


def default_connections(site):
    return DEFAULT_CONNECTIONS.get(site, 512)
```

`--connections` 的默认值由 `512` 改为 `None`，解析出站点后自动套用：

```
site = args.site or (detect_site(args.url) if args.url else None)
if args.connections is None:
    args.connections = default_connections(site)
```

- 迅雷 → 16；其余站点（夸克/UC/百度/123/未知）→ 512，行为与旧版一致。
- 用户显式传 `--connections N` 时仍以用户值为准（覆盖自动值）。
- 好处：迅雷这类"高并发无收益、还更易触发风控"的站点，默认即取合理值。

> 注：迅雷**个人云盘链**（转存后走 `/files/{id}`）建议手动给 1~4，此处仍按分享链场景给 16（保守且够用）。

### 3.5 【可选】本地小 Web UI

他们是网页操作，体验好。我们可以做一个极简本地 Web（`--serve`，只监听 127.0.0.1）：
粘贴链接 → 显示文件列表 → 一键推 Gopeed。不改变现有 CLI。

### 3.6 【不建议学】云端代解析

"把链接交给第三方服务器解析"虽然省 Cookie，但：
- 分享链接与下载行为都要经过第三方；
- 迅雷这类有限速/风控的，只能靠"赞助 + 卡密"来兜成本。
我们的 root 本地方案在这些点上**更干净**，不建议改向。

## 4. 结论

| 问题 | 答案 |
|---|---|
| 对方强在哪 | 站点覆盖、零门槛（无需 Cookie）、完整客户端功能、Gopeed+Aria2 双支持 |
| 我们强在哪 | 隐私本地化、免费、不共享账号、只读更安全、root 方案绕过了失效的签名机制 |
| 本轮已吸收的改进 | **① UA 自动探测**、**② 按站点默认并发**（均已实现并验证） |
| 下一步值得做的 | Aria2 后端 → 站点扩展（阿里/城通/蓝奏优先）→（可选）本地 Web UI |

**一个有意思的印证**：对方把迅雷设为"赞助用户专用，因为账号有下载限制"——
这从第三方角度证实了我们此前的实测结论：**迅雷是这批网盘里最"贵"、限速最狠的一个**。

# 网盘站点评估与集成优先级（阿里 / 城通 / 蓝奏，附四站可借鉴点）

> 目的：决定"下一个要集成哪个站点"，以及从「123 / 夸克 / UC / 百度」这四站能学到什么。
> 所有结论均来自**实测**（本机代理环境），非道听途说。

---

## 一、结论速览

| 站点 | 是否免费 | 能否匿名解析 | 协议难度 | 直链稳定性 | **集成优先级** |
|---|---|---|---|---|---|
| **蓝奏云** lanzou | ✅ 免费（官网："不限速、免登录分享"） | ✅ **全匿名**（已端到端打通） | 中（有 WAF 挑战，已解决） | 好（短时效 token） | ★★★ **首选，已实现** |
| **阿里云盘** alipan | ✅ 免费 | △ 分享 token 可匿名取；下载直链受策略限制 | 中高（有 `x-signature`） | 中（大文件/高码率常需登录） | ★★ 次选 |
| **城通网盘** ctfile | △ 免费版限速严重 | △ 可匿名，但字段多、直链几分钟失效 | 中 | 差 | ★ 低优先 |

一句话：**蓝奏值得马上做（已做完）**；阿里能做但门槛比蓝奏高；城通"能解析但不好用"。

## 二、蓝奏云（lanzou）—— 已实测打通 ✅

### 2.1 免费性证据

- 官网 lanzou.com 明示："**无限制的总存储空间，分享免登录，不限制下载流量，不限速，不限制下载次数**"。
- 实测：无需任何 Cookie / 账号，直接拿到真实文件字节。

### 2.2 协议全貌（实测还原）

```
① 分享页  https://<host>/<id>
     ├─ 经典形态：页面内联 isngis / wp_sign + 提交端点
     └─ 新形态：  <iframe src="/fn?<token>">，真正的 sign 在 /fn 页
② 提交    POST https://apifile.woozooo.com/ajaxfile.php?file=<id>
            （或 apifile.lanzouw.com 备用）
          经典: action=downprocess&sign=<isngis>&kd=1&p=<提取码>
          新态: action=downprocess&websignkey=<ajaxdata>&signs=<ajaxdata>
                &sign=<wp_sign>&websign=&kd=1&ves=1
③ 返回    {"zt":1,"dom":"https://developer4.lanrar.com","url":"?<token>"}
          → 直链 = dom + "/file/" + url
④ 下载 CDN 带 acw_sc__v2（阿里云 WAF）JS 挑战：
          → 算法固定：按位置表重排 arg1，再与固定 KEY 逐字节 XOR 得 Cookie
          → 解出后带 Cookie 即可下载（实测 HTTP 206 + application/octet-stream）
⑤ 文件夹页 /b<id>：POST /filemoreajax.php?file=<id>
          → JSON {"zt":1,"text":[{"id","name_all","size","time"}]}
```

### 2.3 已实现

- 模块：`lanzou.py`（~310 行，零第三方依赖，含独立 CLI）
- 能力：单文件 / 文件夹、经典 / 新样式、带&不带提取码、域名轮换自适应、内置 acw_sc__v2 求解器
- 集成补丁：`panpush-xunlei-lanzou.patch` 中 7 处蓝奏改动（导入/路由/detect_site/choices/COOKIE_GUIDE/_load_saved_cookie/文档串）

### 2.4 注意事项（实测踩坑）

1. **下载 CDN 有频控**：短时间内反复访问同一 `?<token>` 链接，会返回
   "系统发现您的网络异常，需要验证后下载文件" 落地页（HTTP 200 + text/html）。
   因此 `lanzou.py` 只发 **1 次**探测请求解挑战，真正的下载交给 Gopeed；
   正常一次解析+下载不会触发。
2. **Cookie 可复用**：`acw_sc__v2` 在同一链路内可多次使用（实测连用 3 次均 206），
   适合 Gopeed 多连接下载。
3. **直链短时效**：`?<token>` 有时效（页面提示"地址超时，请刷新"），解析后应尽快下载。

## 三、阿里云盘（alipan）

### 3.1 实测结论

- 分享页是 SPA 空壳，配置内联：`client_id = 25dzX3vbYqktVxyX`，
  `pds_endpoint = https://api.aliyundrive.com`。
- 前端的 URL 拼装规则（从 bundle.js 反推）为
  `host + prefix + "/" + version + path`，默认 `version=v2`。
- **实测端点**：`POST https://api.aliyundrive.com/v2/share_link/get_share_token`
  （**无 `/adrive` 前缀**）→ 对伪造 share_id 返回业务级错误
  `{"code":"NotFound.ShareLink",...}`，**证明端点存在且可匿名调用**。
  （加 `/adrive` 前缀反而全部 `NotFound`。）

### 3.2 阻碍

- 请求头需 `X-Canary: client=web,app=adrive,version=v2.3.1`。
- bundle 里存在 `x-signature` 签名（`Z.getSignature()`），网页端调用带签名；
  匿名裸调是否被放行需再用**真实分享链接**验证（本次未能找到可用样例链接）。
- 已知产品策略：阿里云盘**下载直链**对大文件/高码率常要求登录，
  且 `Referer` 有限制（社区普遍反馈"移动端 token 才可下载"）。

### 3.3 优先级

★★ 次选。协议骨架清晰（share_token → list → download_url），
但需要先解决签名/风控与"免登录下载"的可用性验证。

## 四、城通网盘（ctfile）

- 可达：`www.ctfile.com / url56.ctfile.com / url22.ctfile.com` 均 200。
- X网盘助手侧公告："**改成支持分享链接了。不要用 ctfile 链接了**"
  → 说明需支持 `url56.ctfile.com/f/...` 这种分享形态，而非老的 `ctfile.com/fs/...`。
- 其公告还提示"下载速度：国际线路＞电信＞联通＞移动"——**多线路**，需要挑选最优下载 host。
- 免费版限速严重、直链短时效（几分钟）、隐藏字段较多。

**优先级 ★ 低**：能解析，但"好用程度"差，投入产出比低。

## 五、123 / 夸克 / UC / 百度：可借鉴的点

| 可借鉴点 | 来源 | 是否已采纳 |
|---|---|---|
| 平台侧按站点区分并发（迅雷/蓝奏低并发，夸克/百度高并发） | kkjx/123jx/百度站 | ✅ 已采纳（`default_connections()`） |
| 直链来源不同 → 认的 UA 不同 → 自动探测 | 平台 UA 与实测分歧 | ✅ 已采纳（`probe_download_ua()`） |
| **UC 与夸克同一套后端**（都有 `get_stoken.php`），但 UC 免费、夸克收费 | kkjx vs ucjx | 仅作结论（同源，成本差异） |
| 城通"多线路择优"→ 可对下载 host 做择优探测 | ctjx 公告 | 待做（蓝奏/阿里同样受益） |
| 百度站用 `download_threads:64` + 用户自填 token + 指纹 | jiexi/mf | 不采纳（自填 token 违反本地方案"零门槛"目标） |
| 平台"云端代解析" | X网盘助手整体 | ❌ 不采纳（链接经第三方；隐私/收费） |

**难度阶梯**（结合实测）：`蓝奏 ≈ UC ≈ 夸克 ＜ 123 ＜ 阿里 ＜ 城通 ＜ 百度 ≈ 迅雷`。

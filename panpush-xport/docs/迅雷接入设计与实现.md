# 上篇 · 理论

## 1. 范围与结论

本轮目标：给 `panpush` 增加**迅雷云盘分享**的"云解析 + 直推 Gopeed"能力。

结论（已验证）：

| 维度 | 结论 |
|---|---|
| 可行性 | ✅ 端到端跑通：列目录 → 取直链 → 下载 |
| 实现难度 | 比预想低——**不需要复现签名**，root 直读 APP 凭据即可 |
| 架构定位 | **迅雷是唯一必须走 root 的站点**（captcha 只能由 APP 生成） |
| 限速 | 分享直链约 **6 Mbps 上限**；个人云盘直链 ~48 Mbps |

## 2. 协议理论

### 2.1 基本信息

| 项 | 值 |
|---|---|
| API 基址 | `https://api-pan.xunlei.com/drive/v1` |
| 链接形态 | `https://pan.xunlei.com/s/<SHARE_ID>?pwd=<PASSCODE>` |
| `share_id` | 路径段 `/s/` 后到 `?` 前，含 `.` `-` `_` 等字符 |
| 提取码参数 | `pwd=`（也兼容 `pass_code=`） |

### 2.2 请求头（全部必需）

```
Accept: application/json, text/plain, */*
User-Agent: <浏览器 UA>
X-Client-Id: Xqp0kJBXWhwaTpB6        # WEB 端；APP 的 Xp6vsxz_7IYVw2BB 也能用
X-Client-Version: 1.93.8             # 会随版本漂移，做成可配置
X-Device-Id: <设备号>
X-Captcha-Token: ck0.<...>           # 短时效验证码令牌
Referer: https://pan.xunlei.com/
Authorization: Bearer <access_token> # 读分享其实可匿名，但带上更稳
```

### 2.3 端点表

| 用途 | 方法 | 端点 | 关键参数 |
|---|---|---|---|
| 分享根目录列表 | GET | `/share` | `share_id, limit, space, thumbnail_size=SIZE_MEDIUM, scene=NORMAL, pass_code` |
| 分享子目录列表 | GET | `/share/detail` | 同上 + `parent_id, pass_code_token, page_token` |
| 分享单文件直链 | GET | `/share/file_info` | `share_id, file_id, pass_code, pass_code_token, folder_id, space, scene=NORMAL` |
| 转存（写，本实现不用） | POST | `/share/restore` | — |
| 转存进度轮询 | GET | `/tasks/{id}` | — |
| 个人云盘列表 | GET | `/files` | `parent_id, limit, space` |
| 个人云盘取直链 | GET | `/files/{id}?space=&usage=CONSUME` | `usage=CONSUME`（`DISPLAY` 返回空链） |

### 2.4 响应结构与解析要点

- 文件列表在 `files[]`（**不要**回退到推荐位/资源数组，那些与分享无关）。
- 条目字段可能多种命名，需兼容：
  `id|file_id|fileId`、`name|file_name|fileName`、`size|file_size|fileSize`、
  目录判定 `kind in (drive#folder, folder) | is_dir | file_category==FOLDER`。
- 直链可能在列表里就已经内联给出（`web_content_link` / `links.download` 等）；
  没有才需要再打 `/share/file_info`。
- 分页：`next_page_token` / `page_token_next`。
- 提取码令牌 `pass_code_token` 由 `/share` 首次响应返回，后续请求回填。

### 2.5 画重点（易错）

| 项 | 说明 |
|---|---|
| 根目录 `parent_id` | 根用**空串**；用 `"0"` 会被当成真实 id → `file_not_found` |
| 直链 UA | 下载 `web_content_link` **只认 `okhttp/4.9.0`**（浏览器 UA / Thunder UA / 带 Authorization 全 403） |
| 直链 host | `vod*-h0*-vip-lixian.xunlei.com`，会变，不要写死 |

## 3. 认证理论（本方案的核心）

### 3.1 三件套

| 用途 | 来源（APP 私有目录 `shared_prefs/`） | 键 |
|---|---|---|
| `Authorization` | `auth_pref.xml` | `credentials_<CLIENT_ID>` → JSON 的 `access_token`（`Bearer` JWT，2h 有效，APP 自动续期） |
| `X-Captcha-Token` | `xl-acc-captcha-token.xml` | `*captchatoken`（`ck0.` 前缀） |
| `X-Device-Id` | `__device_info_new__.xml` | `device_id_new` |

### 3.2 为什么不能自己生成 captcha 令牌

网页端当前（`1.93.8`）通过 `utils-initial.js` 拿到：

```
signKey  = "k&&9(rT5LU"
funName  = "pubqKytV9pQyXvHAKg2SfabUzJeb1FtK4Rg"
funFile  = "code-res"     ← 关键分流开关
```

- `funFile == "code-res"` → 走**公钥签名**（`getPubKeySignUtil`）；
  否则才走老的"14 盐 MD5 链"（参考实现用的旧机制）。
- 该签名模块是**白盒混淆**：每个 `pub*` 函数是 `md5(输入+随机盐)` 后跳到另一个混淆函数，
  甚至跨模块自引用（模块 13 引用 `t(13)` 自身）。**手写移植不现实。**
- 盐链服务端域名 `risk-account-ssl.office.k8s.xunlei.cn` 在本网络不可达。

→ 结论：**放弃代签，改为"借"APP 已签好的令牌。**

### 3.3 captcha 令牌的生命周期（实测）

- `expiresat` 是**毫秒**时间戳；令牌寿命仅**几分钟**。
- **键名易错**：后缀 `captchatoken` 长度是 **12**，前缀 = `key[:-12]`；
  写错会导致 `expiresat` 取不到 → 排序失效 → 一直用旧令牌 → `验证码无效`。
- 服务端**严格程度不一致**：
  - `GET /files`（列表）：令牌过期仍可能 200（宽松）
  - `GET /files/{id}?usage=CONSUME`、`/share/*`：过期即 400 `captcha_invalid`（严格）
- **刷新触发条件（关键）**：
  - 只是启动 APP 首页 → **不会**刷新；
  - 必须让 APP 处理一次**分享深链**（或相关下载页）才会申请新令牌。
  - 触发命令：
    ```
    am start --user 0 -a android.intent.action.VIEW \
      -d 'https://pan.xunlei.com/s/<SHARE_ID>?pwd=<PWD>' -p com.xunlei.downloadprovider
    ```
    约 6~10s 后 `xl-acc-captcha-token.xml` 出现新条目（实测由 3 条变 4 条）。

→ 设计推论：解析器解析某分享时，若令牌过期，**正好用这个分享链接**去触发刷新，
   然后重读、重试。自洽且零额外输入。

### 3.4 安全与代价（必须向用户说明）

- 拿到的是**迅雷 APP 的账号令牌**，等同账号登录态；只应存在本机、勿外发。
- `auth_pref.xml` 会被 APP 自己刷新，所以**每次运行实时读取**比落盘缓存更好。
- 转存（写操作）会真往"我的云盘"写文件 → 本实现**默认不做写操作**。

## 4. 限速与 UA 理论

### 4.1 同一文件的两条路径（实测 `Smart Tool v3.0.exe` 45.9 MB）

| 路径 | host | 1 连接 | 4 连接 | 16 连接 |
|---|---|---|---|---|
| 分享直链 `/share/file_info` | `vod0100-h04-vip-lixian` | 0.14 | 0.54 | **0.69 MB/s** |
| 个人云盘直链 `/files/{id}?usage=CONSUME` | `vod0095-h04-vip-lixian` | **5.88** | 5.76 | 4.81 MB/s |

（MB/s；个人云盘 1 连接即跑满 ~49 Mbps）

**结论**：限速锚在**"分享访问路径"**上，不在 CDN 主机上（两者 host 同域）。
- 分享链被限到 ~6 Mbps，多连接可缓解（4 连已达 78%）但不能突破；
- 个人云盘链不受限。

### 4.2 对推送 Gopeed 的指导

| 场景 | `connections` | 备注 |
|---|---|---|
| 分享直链 | 8 ~ 16 | 上限 ~6 Mbps |
| 个人云盘直链 | 1 ~ 4 | 再多无益 |

且**必须**在 `req.extra.header` 里塞 `User-Agent: okhttp/4.9.0`，否则 403。

# 下篇 · 实现与集成

## 5. 模块结构（`panpush/xunlei.py`）

```
常量区        API_BASE / CLIENT_ID / CLIENT_VERSION / UA_APP / UA_DL / PREFS ...
工具函数      _http / _get / _parse_json / human_size
              extract_passcode / extract_share_id

凭据层        _parse_pref(path)                 Android XML → dict
              _latest_captcha(pref)             取有效期最长令牌（含 k[:-12] 坑）
              read_app_creds()                  root 直读三件套
              read_saved_creds()                读 .cookie.xunlei
              load_creds()                       实时直读优先，落盘兜底
              captcha_fresh(creds)               新鲜度判断
              refresh_captcha(share_url)         用分享深链触发 APP 刷新

解析层        class XunleiParser
                __init__(url, passcode, cookie, timeout, token=)
                _headers()                        组装请求头
                _api(path, params)                请求 + 错误分类 + 自动刷新重试
                list_files(parent_id=None)        递归列目录（/share, /share/detail）
                get_downloads(files)              /share/file_info → 直链 + UA 头
                parse(list_only=False)            对外统一返回

异常          XunleiCredsError / XunleiCaptchaError

CLI           python3 xunlei.py '<链接>' [--list-only]
              python3 xunlei.py --creds
```

## 6. 算法流程

```
parse(url):
  1. share_id ← extract_share_id(url)；passcode ← 参数或 ?pwd=
  2. creds  ← load_creds()
       ├─ read_app_creds()（root 直读 APP，最新）
       └─ 失败 → read_saved_creds()（.cookie.xunlei）
     都无 → 抛 XunleiCredsError(带配置指引)
  3. 若 captcha 过期 → refresh_captcha(url)（分享深链触发）→ 重读
  4. files ← list_files()
       /share       取根列表 + pass_code_token
       遇目录 → /share/detail(parent_id, pass_code_token) 递归
  5. list_only ? 返回 files
  6. downloads ← 对每个文件：
       条目内有内联直链 → 直接用
       否则 /share/file_info → web_content_link
       组装 headers = {"User-Agent": "okhttp/4.9.0"}
  7. 返回 {site, files, downloads}

_api() 错误处理:
  若 error_code==9 或 desc 含 captcha
     → 未重试过则 refresh_captcha 后重试一次
     → 否则抛 XunleiCaptchaError（带人话提示）
```

## 7. 与 `panpush.py` 集成（精确改动）

> 以下为**需要写的确切代码**，交给 harness 直接落进 `panpush.py` 即可。
> 共 5 处，均在文件内已有同类约定旁。

### 7.1 顶部 import（文件头 import 区）

### 7.2 路由表 `PARSERS`（约第 1141 行，替换原占位行）

### 7.3 `detect_site()`（约第 1153 行，return None 之前加）


### 7.4 CLI `--site` choices（约第 1302 行）

```python
    ap.add_argument("--site", default=None, choices=["quark", "uc", "baidu", "123", "xunlei"],
                    help="显式指定站点（用于 --check-cookie / --save-cookie）")
```

### 7.5 避免通用 Cookie 加载误伤迅雷（`_load_saved_cookie` 内）

`xunlei.py` 自己管凭据，`.cookie.xunlei` 是 `key=value` 多行格式，**不是** Cookie 串，
不要让通用加载器把它当 Cookie 传进来。在 `_load_saved_cookie(site)` 开头加：

```python
    if site == "xunlei":
        return None, None      # 迅雷凭据由 XunleiParser 内部处理
```

### 7.6 可选：`COOKIE_GUIDE` 补一条（便于报错时给指引）

```python
COOKIE_GUIDE["xunlei"] = XUNLEI_GUIDE
```

### 7.7 可选：`check_cookie` 支持迅雷

```python
    if site == "xunlei":
        try:
            import xunlei as _xl
            c = _xl.load_creds()
            if not c:
                return False, "未找到凭据（需 root 直读 APP 或提供 .cookie.xunlei）"
            if not _xl.captcha_fresh(c):
                return None, "captcha 令牌已过期（解析时会自动触发刷新）"
            return True, "有效（device %s…）" % c["device_id"][:12]
        except Exception as e:
            return None, "校验异常: %s" % e
```

### 7.8 不需要改的地方

- `main()` 主流程、Gopeed 推送逻辑**完全不用动**：
  `XunleiParser.parse()` 返回结构与其它站点一致，
  `downloads[].headers` 会被 `Gopeed.add_task/add_batch` 自动塞进 `req.extra.header`。
- `getcookie.py` **不需要**加迅雷：它面向"单串 Cookie"，而迅雷要三件套且在
  `xunlei.py` 内已处理。保持职责分离。

## 9. 风险与已知限制

1. **依赖已登录的迅雷 APP**：APP 被卸载/未登录/清数据 → 无凭据。
2. **需要 root**：`/data/data` 只有 root 可读。这是迅雷唯一站点必须的。
3. **`am start` 会短暂把 APP 弹到前台**：自动刷新时用户可见；可用环境变量
   `XUNLEI_NO_AUTO_REFRESH=1` 关闭。
4. **版本漂移**：`CLIENT_VERSION`（当前 `1.93.8`）、端点参数、字段命名可能变；
   已把它们集中成常量，便于更新。
5. **写操作未纳入**：转存 `/share/restore` 未实现、未测试。若将来要加，务必
   先确认（会真实写入用户云盘）。
6. **限速天花板**：分享链 ~6 Mbps，属服务端策略，非代码可解。

## 10. 与"个人云盘路径"的关系（建议）

- 若目标文件在**自己云盘**里（或已转存），优先走 `/files/{id}?usage=CONSUME`，
  速度约为分享链的 6~8 倍。
- 因此 `XunleiParser` 的**未来增量**（非本期）：加一个
  `resolve_from_personal(file_id_or_path)` 分支，在"转存后"或"自己的分享"场景下
  自动切到快路径。本期只读分享路径，接口已预留（`usage=CONSUME` 已实测可用）。

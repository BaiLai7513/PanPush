# Voyage（`com.lx.lushuo.gjx.xjg`）五站网盘「文件管理」接口梳理与借鉴

> 目标：把 Voyage 登录后**内部怎么管理网盘文件**（列目录 / 上传 / 下载 / 分享 / 转存 / 回收站等）
> 从 APK 里静态扒出来，整理成 123 / 夸克 / 百度 / 阿里 / 迅雷 五站对照，供 panpush 解析器借鉴。

## 0. 方法与局限（先看这段）

- **数据来源**：`/sdcard/Make/lushuo/base.apk`（95 MB 单 base.apk，v1.0.11，targetSdk=37）
  内 `classes*.dex` 的**字符串常量**（`[\x20-\x7e]{4,}` 提取）+ 中文 UI 文案（`[\u4e00-\u9fff]{2,12}`）。
  扫描脚本：`scan_api.py` / `scan_api2.py` / `scan_attr.py` / `scan_site.py` / `scan_cjk.py`。
- **归属判定**：dex 字符串池里 **URL 路径与主机名是分开存储的**，无法从字符串顺序直接配对。
  因此本文的"某路径属于某站"是**依据各站公开接口的命名特征推断**，逐条标注 **置信度**：
  - `高`＝同时命中该站**域名**与**特征路径**（如 `/adrive/`、`/b/api/`、`/1/clouddrive`）；
  - `中`＝路径命名高度吻合该站公开接口，但未见完整主机拼接；
  - `低`＝只确认了入口域名，接口未还原。
- **重要**：全部接口**均来自静态分析，未经真实登录调用验证**；参数名、签名头、Cookie 均未在本文展开。
- 该 App 是"全能"型（视频解析 / 书源 / 漫画 / 菜谱 / 语音…），字符串噪声极大，本文只保留**网盘文件管理**相关项。

## 5. 对 panpush 的借鉴（可落地项）

1. **抽象统一文件管理接口**：定义
   `list / mkdir / rename / move / copy / delete(trash) / search / download_url / upload(pre→auth→finish) / share_resolve(token→detail→save)`，
   每站一个 Adapter，参照上表把路径填进去即可。
2. **分享转存三段式**（五站共性）：
   阿里 `getShareToken`→`saveFile`；夸克 `sharepage/token`→`detail`→`save`；百度 `share/get`→`share/download/info`。
   建议 panpush 的"分享解析"统一按 `token→列表→转存` 建模。
3. **上传分片协议**：先 `upload_request`/`upload/pre`（拿分片上传地址 + 凭证）→ 逐片 PUT → `upload_complete/finish`；配合**秒传校验**（阿里/123/夸克均有），可大幅省流。
4. **下载直链**：优先取 `get_download_url` / `download_info` / `getDownloadUrl`，并处理**直链过期**（文案里"直链已过期""播放地址已失效"高频）需自动重取。
5. **回收站与删除语义**：各站删除**默认进回收站**（阿里 `/v3/file/delete`、百度 `trash`、夸克 `recyclebin/trash`）；panpush 做删除时要区分"进回收站 / 彻底删除"。
6. **风控/中转的取舍**：Voyage 用**自有后端 `/userres/v1/*` 中转**换来稳定与宽松风控；panpush 当前选择**本地直连**各站官方 API——**更透明、无第三方依赖**，但要自己处理签名与风控（这也正是它卡滑块、而 Voyage 不卡的原因之一）。
7. **多账号**：Voyage 支持多账号并存（`多账号管理`/`切换账号`），文件列表按当前账号过滤 —— panpush 若要支持多账号，接口层要带账号维度。
